Q10. Scope and variable declarations

var amount = 100;
function calculate() {
  var amount = 200;
  let discount = 20;

  if (true) {
    var amount = 300;
    let discount = 50;
    console.log(amount, discount); // 300 50
  }

  console.log(amount, discount); // ReferenceError
}

calculate();
console.log(amount); // 100

Output order:
300 50
ReferenceError

Explanation:
- amount uses var, so it is function-scoped. The inner var amount = 300 reassigns the same variable.
- discount uses let, so it is block-scoped. The discount inside the if block is different from the discount outside it.
- The line `console.log(amount, discount);` outside the if block uses the outer `discount` declared by let, which is not available inside the if block, so it throws a ReferenceError.

Q14. Rest parameters and spread syntax

  return numbers.length;
}

Q16. Fix the shopping cart calculation

Original code:
function calculateCartTotal(...prices) {
  let total = 0;
  for (let i = 0; i <= prices.length; i++) {
    total += prices[i];
  }
  return total;
}
console.log(calculateCartTotal(100, 200, 300));

Problem:
The loop condition is `i <= prices.length`, which runs once too many times. At `i = prices.length`, `prices[i]` is `undefined`.

Correct code:
function calculateCartTotal(...prices) {
  let total = 0;
  for (let i = 0; i < prices.length; i++) {
    total += prices[i];
  }
  return total;
}

console.log(calculateCartTotal(100, 200, 300)); // 600

Q17. Fix the object method

const user = {
  userName: "Rahul",
  showName: () => {
    console.log(this.userName);
  }
};

user.showName();

Problem:
Arrow functions do not have their own this. They inherit this from the surrounding lexical scope, which is not the user object in this case.

Correct code:
const user = {
  userName: "Rahul",
  showName() {
    console.log(this.userName);
  }
};

user.showName(); // Rahul

When arrow functions are appropriate:
- When you want to preserve the surrounding this value inside callbacks or event handlers.
- Example: array map/filter callbacks, setTimeout inside class methods, or React event handlers.

Q18. Type Coercion — Predict the Output

console.log([] + []);        // ""
console.log([] + {});        // "[object Object]"
console.log("5" - - "2");  // 7
console.log(null + 1);       // 1

Explanation:
- [] + [] => both arrays become empty strings and concatenate to "".
- [] + {} => [] becomes "" and {} becomes "[object Object]"; result is "[object Object]".
- "5" - - "2" => unary minus converts "2" to -2, so expression becomes 5 - (-2) = 7.
- null + 1 => null becomes 0, so 0 + 1 = 1.

Q19. Scope and Hoisting

console.log(a);
var a = 10;

console.log(b);
let b = 20;

Output:
undefined
ReferenceError

Explanation:
- `var a` is hoisted to the top of its scope and initialized to undefined. So `console.log(a)` prints undefined.
- `let b` is also hoisted, but it is placed in the Temporal Dead Zone (TDZ) until its declaration is executed. Accessing it before initialization throws a ReferenceError.

Temporal Dead Zone (TDZ):
- The TDZ is the period between hoisting and initialization where let/const variables cannot be accessed.
- This prevents use before declaration and helps catch bugs earlier.

JavaScript Interview-Level Questions

1. Difference between == and ===
`==` compares after type coercion.
`===` compares both value and type without coercion.

Example:
5 == "5" // true
5 === "5" // false

2. Difference between undefined and null
undefined means a variable has been declared but no value assigned, or a property does not exist.
null means an intentional empty value.

3. Difference between for...in and for...of
for...in iterates over keys/indexes.
for...of iterates over values of an iterable object like an array.

4. Can a function return another function?
Yes.

Example:
function multiplier(factor) {
  return function (value) {
    return factor * value;
  };
}

const double = multiplier(2);
console.log(double(5)); // 10

Use case: creating reusable closures, factory functions, and higher-order functions.

5. What happens if a function has no explicit return statement?
It returns undefined by default.

6. Difference between passing a primitive value and passing an object to a function
Primitive values are passed by value, so changes inside the function do not affect the original value.
Objects are passed by reference, so changes to object properties inside the function affect the original object.

7. Difference between shallow copy and deep copy
Shallow copy copies only the top-level properties. Nested objects are still shared.
Deep copy creates a fully independent duplicate of all nested objects and arrays.

8. Why is NaN !== NaN true?
Because NaN is a special value defined by the IEEE 754 standard, and it is not equal to itself.

9. Difference between function declarations and function expressions regarding hoisting
Function declarations are hoisted fully and can be called before declaration.
Function expressions are not hoisted in the same way; the variable is hoisted but not initialized until the assignment line runs.

10. When would you use an arrow function instead of a regular function?
Use arrow functions when:
- you want shorter syntax,
- you want to keep the lexical this value,
- you are writing callbacks.

Avoid arrow functions when:
- you need your own this,
- you need a constructor,
- you need method definitions inside objects.
